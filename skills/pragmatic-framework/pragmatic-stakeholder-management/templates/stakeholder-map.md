## Instructions

Build this map before the communication plan (`communication-plan-template.md`). The map answers *who matters, how much, and what they need from you*. The RACI answers *who decides what*. Together they prevent the two most common stakeholder failures: surprising someone who could block you, and arguing about a decision nobody knew they owned.

1. List every person or group that is affected by, contributes to, or can block the work: leaders, teams and partners, internal and external.
2. Rate interest and influence (High / Medium / Low).
3. Write what each one needs from you in one line. Be specific: "release dates two sprints ahead for staffing," not "updates."
4. Set cadence, channel and an owner on your side.
5. Fill in the RACI for the decisions that will come up on this initiative.
6. Share the map with your own leadership and core team so it isn't just in your head. Keep sensitive notes (e.g., about individuals' positions) appropriately restricted.

### Interest / Influence Grid

Place each stakeholder in a quadrant to set the level of engagement:

|  | **Low interest** | **High interest** |
|---|---|---|
| **High influence** | **Keep satisfied** — concise, outcome-focused updates; consult before decisions that affect them | **Manage closely** — involve in key decisions; regular one-to-one time; no surprises |
| **Low influence** | **Monitor** — broad updates (newsletter, release notes) | **Keep informed** — regular, detailed updates; invite feedback |

Watch for stakeholders whose influence is rising (new leader, reorg, budget shift) and move them before they move you.

## Part 2: Decision RACI

List the key decisions on this initiative and who plays which role. Exactly one **A** per decision.

- **R — Responsible:** does the work to reach the decision
- **A — Accountable:** makes the final call and owns the outcome
- **C — Consulted:** gives input before the decision (two-way)
- **I — Informed:** told after the decision (one-way)

| Key decision | Product Mgmt | Engineering | Design | Marketing | Sales | Support / CS | Exec sponsor | Partners |
|---|---|---|---|---|---|---|---|---|
| Which market problems to solve next | A/R | C | C | C | C | C | I | |
| Release scope and trade-offs | A | R | C | I | I | I | I | |
| Release date / timing | C | A/R | I | C | I | I | I | I |
| Positioning and messaging | A (positioning) | I | I | R (messaging) | C | I | I | I |
| Pricing and packaging change | R | I | | C | C | I | A | I |
| Launch go / no-go | R | C | I | C | C | C | A | I |
| Roadmap changes shared externally | A | C | | R | C | I | C | I |
| | | | | | | | | |

*Adjust columns and assignments to your organization. If two people both believe they are "A" for a decision, resolve it now, not mid-crisis.*
