# Sales Tools — Pragmatic Framework (Enablement Category)

## Framework Context

**Official Definition**: "Create tools for salespeople focused on a specific step of the selling process."

Sales Tools is one of four activities in the **Enablement** category of the Pragmatic Framework, alongside Sales Alignment, Content, and Channel Training. Where Content develops broad go-to-market materials and Channel Training teaches reps *how* to sell, Sales Tools provides the specific instruments reps reach for during live selling moments.

The key distinction: every sales tool must be designed for a **specific step** of the selling process, not as a general-purpose document. A tool that tries to serve every situation serves none of them well. Think of sales tools like a carpenter's toolkit — the rep's skill lies in knowing which tool to use and when.

## Prerequisites from Other Framework Activities

Sales Tools depends heavily on upstream Pragmatic activities. Before building effective tools, confirm the user has (or is developing) these inputs:

- **Positioning** (Planning) — The internal positioning document that anchors all messaging
- **Buyer Personas** (Planning) — Archetypical buyers whose problems, language, and priorities shape each tool
- **Buyer Experience** (Planning) — The documented buyer journey that determines *which* selling steps need tools
- **Competitive Landscape** (Market) — Assessed competitor strengths, weaknesses, and strategies
- **Win/Loss Analysis** (Market) — Insights into why deals are won or lost and what steps buyers took
- **Market Problems** (Market) — Validated, pervasive problems that drive urgency

If these inputs are incomplete, help the user identify the gaps and consider whether to address them first or proceed with the information available.

## Workflow

Follow these six steps to guide the user through creating effective sales tools:

### Step 1: Map the Selling Process to the Buyer Journey

Before creating any tool, identify the specific steps in the selling process where reps need support. Align these to how the market wants to buy (from the Buyer Experience activity).

Common selling steps that need tool support include: initial prospecting and outreach, discovery and qualification, solution presentation and demonstration, competitive differentiation, proposal and negotiation, and closing and commitment.

Ask the user which selling steps their reps struggle with most, or where deals tend to stall or get lost. Prioritize tools for those steps first.

### Step 2: Identify the Tool Type

Based on the selling step identified, recommend the appropriate tool type. Read `references/tool-types.md` for detailed guidance on each type, including when to use it and what to include.

The major categories of sales tools are:

- **Battle Cards** — Competitive intelligence for handling rival comparisons in-call
- **Objection Handling Guides** — Pre-crafted responses to common buyer pushback
- **ROI Calculators / Value Tools** — Help buyers quantify the financial case
- **Demo Scripts** — Modular presentation guides organized by topic, not monolith
- **Prospecting Scripts** — Navigable outreach scripts segmented by buyer type
- **Qualification Checklists** — Criteria to assess deal viability at each stage
- **Reference Sheets** — Quick-access product facts, pricing, and proof points
- **Pain/Discovery Sheets** — Persona-specific problem maps with probing questions
- **Proposal Templates** — Structured frameworks for presenting solutions

### Step 3: Align Tool Content to Buyer Personas

Each tool should speak to a specific buyer persona's priorities, language, and concerns. A tool for an economic decision-maker emphasizes different things than one for a technical evaluator.

For each tool, determine:

- Which persona(s) will the rep be engaging when using this tool?
- What problems does this persona care about most?
- What language and terminology does this persona use?
- What objections or concerns are typical for this persona?
- What proof points (case studies, data, references) resonate with this persona?

### Step 4: Draft the Tool Using the Appropriate Template

Read `references/tool-types.md` for structural guidance on the specific tool being created. Use the templates in the `templates/` directory as starting frameworks:

- `templates/battle-card-template.md` — For competitive battle cards
- `templates/objection-handler-template.md` — For objection handling guides
- `templates/sales-tool-audit-template.md` — For auditing existing tool coverage

Key design principles for all sales tools:

1. **One tool, one purpose** — Each tool targets a specific selling step and scenario
2. **Modular and navigable** — Reps must be able to jump between sections during live calls
3. **Skimmable under pressure** — Bold key phrases, use short blocks, avoid dense paragraphs
4. **Persona-specific language** — Mirror the buyer's vocabulary, not internal jargon
5. **Evidence-backed** — Include specific proof points, not vague claims
6. **Current and maintained** — Build in a review cadence from the start

### Step 5: Create Guidance for Tool Usage

A tool without usage guidance becomes a blunt instrument. For each tool created, provide:

- **When to use it** — The specific selling moment or trigger that calls for this tool
- **How to navigate it** — Which sections to lead with based on the conversation flow
- **What to customize** — Which elements reps should tailor for each specific prospect
- **What not to do** — Common misuses (e.g., reading a battle card verbatim to a prospect)

This guidance is what separates effective sales enablement from a document dump.

### Step 6: Plan the Tool Lifecycle

Sales tools decay rapidly. Establish a maintenance plan:

- **Review trigger events**: New competitor moves, product launches, pricing changes, lost deals revealing new objections
- **Review cadence**: Quarterly at minimum; competitive tools may need monthly updates
- **Feedback loop**: How reps report what's working, what's missing, and what's outdated
- **Ownership**: Who is responsible for updates (typically product marketing)
- **Measurement**: Track tool adoption rates, influence on win rates, rep satisfaction scores

## Pragmatic Principles to Emphasize

- **NIHITO (Nothing Important Happens In The Office)**: The best sales tools are built from actual buyer conversations and field feedback, not conference room assumptions
- **Outside-in thinking**: Tools should reflect how the *market* buys, not how the *company* sells
- **Problems first**: Every tool should connect back to validated market problems, not feature lists
- **Selling the product, not using it**: Sales tools focus on *why to buy*, not *how to use* — that's training's job
